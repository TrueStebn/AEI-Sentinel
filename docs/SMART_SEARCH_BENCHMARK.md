# Measured local model comparison

Historical Phase 14 evidence. Phase 15 pins only Qwen3 8B/Q4_K_M and its recorded full digest. 4B is no longer an accepted runtime override. No model comparison was rerun in Phase 15.

Measured on 2026-10-17 using Ollama 0.31.2, an RTX 4070 SUPER (12 GB), i5-14600K and 32 GB host RAM. Both candidates used Q4_K_M, temperature 0, seed 14, thinking disabled, a 4,096-token context, 500-token generation cap and the same structured schema, terminology and six contract examples. No 14B or larger model was loaded or evaluated.

**Selected default: `qwen3:8b`.** Its full-pipeline exact accuracy is 6.25 percentage points higher than 4B, exceeding the approximately five-point preference margin for the smaller candidate. It also handles the tested male/female comparisons without the clarification required by 4B. The additional latency and residency fit the measured GPU budget.

## Separate model and pipeline measurements

The 64 explicit goldens include 36 executable queries and 28 requests that must be held for clarification. Pipeline exactness includes deterministic source validation, known numeric-boundary normalization and correct clarification reasons. It must **not** be described as the language model alone achieving that accuracy. Raw model exactness below includes only catalog aliases and its own integer-boundary flags, without semantic repair or safety guards.

| Measurement | qwen3:4b | qwen3:8b |
|---|---:|---:|
| Raw model exact interpretation | 42/64 (65.62%) | 46/64 (71.88%) |
| Complete pipeline exact interpretation | 59/64 (92.19%) | 63/64 (98.44%) |
| Executable queries answered correctly | 33/36 | 35/36 |
| Invalid/ambiguous requests safely held | 28/28 | 28/28 |
| Exact clarification reason after validation | 26/28 | 28/28 |
| Exact clarification by raw model alone | 12/28 | 13/28 |
| Wrong queries accepted after validation | 0 | 0 |
| Median warm inference | 1.404 s | 1.780 s |
| p95 warm inference (nearest rank) | 1.464 s | 1.863 s |
| Ollama-reported VRAM residency | 3.18 GB | 5.58 GB |
| GPU memory snapshot including desktop/other use | 6,253 MiB | 8,543 MiB |
| Ollama GPU placement | 100% GPU | 100% GPU |
| Separate final-run warm-up request | 4.611 s | 2.264 s |

The warm-up times are not controlled cold-boot benchmarks: 8B was already resident, while 4B had been explicitly unloaded and then loaded from cached weights. The first development requests took 67.60 s (4B) and 20.71 s (8B), including different host/driver/cache conditions. Do not infer that 8B intrinsically loads faster. The app has a 45-second timeout; a cold load may require explicit warm-up/retry, and Manual Search remains available. Per-process CPU/RAM peaks and concurrent public load were not measured. VRAM figures are Ollama residency estimates and one GPU snapshot, not guaranteed peaks.

## Remaining measured limitation

Both candidates withhold `q35`: "Show historical baseline resistance for E. coli and CIP." The operation is available through Manual Search (Resistance summary, Historical baseline); the model returns an inconsistent/unsupported intent, so the UI refuses to broaden the request. 4B additionally withholds the two male/female patient-group queries q23/q24 and reports a less precise clarification reason on two invalid requests. The chosen 8B handles those group queries. Review the recognised parameters; this finite development fixture cannot establish arbitrary-language safety or clinical validity.

## Reproducibility and evaluation boundaries

Expectations were explicitly authored and reviewed before inference, not generated by either model. A first development pass exposed inconsistent ready/unsupported output and operation/default mistakes. Six contract examples were then added and one final sequential 64-query run was conducted for each of the same two candidates. No other model family/size was explored. Saved real responses from that final prompt are scored using the identical final validator for both candidates; original response bodies and measured inference timings are retained. Numeric normalization changes scoring, not the recorded model output. This is **development-set evaluation, not a held-out test or clinical validation**.
